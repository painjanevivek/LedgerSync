### A03 — Extend the state model and prove defect detection

Priority: high for the complete R08 verification claim. Owner role: financial test maintainer. Plan: R08 steps 1, 4–5, 9, 13 and 16.

The independent oracle is real and useful. It uses wide integer arithmetic, predicts outcomes before database calls and checks journals, versions and immutable records. The generated operation list is transfer, replay, conflict, funding, correction, lost response, rollback, same-intent concurrency and insufficient funds. The reservation model adds separate obligation coverage.

The core oracle does not represent account lifecycle or an independent actor/approval state machine. Separate application tests cover several of these rules; the gap is their stateful combination and independent prediction.

The concurrent core case sends four copies of one intent. It does not record general invocation/response histories and compare competing operations with valid serial orders. The minimizer test proves reduction of a synthetic cause/effect sequence. The injected outbox failure proves rollback. Neither proves that the whole harness detects deliberately introduced duplicate posting, missing authorization or unbalanced entries. No such retained trial was found.

Complete this item with bounded lifecycle/authority histories, competing-operation histories and a small serial-order checker. Run deliberate safe test mutations in a disposable harness. Retain the detected failure class and reduced input. Do not ship mutated financial code.
